Who We Are and What This Covers

This Privacy Policy explains how [OPERATOR NAME] (the "Operator", "we") handles information when you use the FlawRadar web security checker (the "Service"). For information that identifies a person, the Operator is the controller (the party that decides how and why it is used). Words defined in the Terms of Service have the same meaning here.
This policy describes how the Service is built to work. The Service is open about this because it is meant to be checked: the way each kind of data is handled below is how the software behaves.

Information About the Websites You Scan

To produce a Report the Service reads what a Target sends to any visitor: response headers, certificate details, DNS records, the home page and well-known files. It keeps only the findings and short excerpts needed to explain them. It does not intentionally collect personal data from Targets. Some public information can include personal data, for example an email address in a security contact file, and if so it may appear in a Report and is kept and deleted with that Report.
The Target's operator will see requests from the Scanner Addresses with a FlawRadar user agent in their own logs.

Uploaded Source Code

Files you upload are sent to the Service, analysed by automated pattern checks in the server's memory, and discarded when the response is sent. They are not written to disk, not placed in a log, not included in any stored Report, not read by a person, and not used to train any model. Zip files are opened in memory and are not extracted to disk.
The results are returned only to your browser. A finding shows the file name, the line number and the line itself. Where the Service recognises a secret (for example a cloud key or a token), it shows only the first characters of it. Other sensitive text on the same line may appear in the result that is returned to you, and the result is not stored by the Service. Your browser and any device you use may keep it, so close the page when you are done.
Do not upload secrets or personal data of other people. If you would prefer that your code does not leave your computer, you can run FlawRadar yourself; the project's README explains how.
The Service is hosted on infrastructure that may handle memory in ways outside our control (for example swap files or crash diagnostics). We have not designed the Service to retain uploaded code, but we cannot promise that no trace could ever exist at the infrastructure level.

You can clear it in your browser settings. The Service ignores "Do Not Track" signals only because it does not track.
