Questions

How does a scan work?
  1. FlawRadar looks up the host name and refuses anything that points at a private network.
  2. It loads the home page over HTTPS, falling back to HTTP, and reads the headers and cookies.
  3. At the same time it opens a TLS connection, makes one request to port 80, reads DNS records, and looks for /.well-known/security.txt.
  4. Each check is scored, and the report lists the fix for every problem.
What does FlawRadar look at?
Transport
HTTPS, the redirect from HTTP, certificate validity and key size, and whether TLS 1.0 and 1.1 are still accepted.
Headers
HSTS, Content-Security-Policy, X-Content-Type-Options, clickjacking protection, Referrer-Policy, Permissions-Policy, CORS, and version numbers in the Server header.
Cookies and content
Secure, HttpOnly and SameSite flags, mixed content, third-party scripts without integrity hashes, and password forms.
DNS and mail
SPF, DMARC, CAA and security.txt.
Exposure (deep scan only)
Exposed Git folders, environment files, backups, debug pages, directory listings and risky HTTP methods.
My firewall blocked the scan. What now?

Bot filters and web application firewalls often block scanners they have not seen before. When that happens FlawRadar says so instead of grading the firewall's error page. Add the scanner addresses to your allow list and scan again. The whitelist page has the addresses and the rules.

Can I scan any website?

No. Scan only sites you own or have written permission to test. Scanning someone else's site without permission can be illegal. Only public sites can be scanned, and FlawRadar refuses private and internal addresses. Site owners can ask to be excluded; see the Acceptable Use Policy.

What does FlawRadar send and keep?

A normal scan makes about eight read-only requests. Reports are kept for a limited time and then deleted. Source code is checked in your browser and never sent to FlawRadar. FlawRadar sets no cookies. The Privacy Policy lists every kind of data and how long it is kept.
