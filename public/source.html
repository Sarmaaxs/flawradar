Open CVE intelligence beta

Check your source code

Drop the folder (or a .zip) of your website's code. Your browser reads it for hard-coded secrets, SQL injection and cross-site scripting patterns, shell commands built from strings, weak crypto, turned-off TLS checks, and risky settings in config and dependency files.

Your code stays on your computer. The check runs inside this page, in your browser. Your files are not sent to FlawRadar, not stored, and there is no report or link to share. The one thing that does leave is the list of package names and versions from a lockfile, sent to look up known vulnerabilities. You can confirm this: open your browser's developer tools, look at the Network tab and drop a folder. Secrets found in the code are shown only as the first few characters.

What this can and cannot do

  • It matches patterns line by line. It finds the common, obvious mistakes. It does not follow data from a request to a database call, so it will miss bugs that are spread over several lines or files, and logic errors such as missing permission checks.
  • Some matches are lookalikes. Each finding says how sure the rule is (high, medium or low confidence). Read the line before changing anything.
  • It looks up known vulnerabilities in dependencies via the OSV database when a lockfile or pinned requirements file is present. Coverage is not complete; also run npm audit, pip-audit or osv-scanner in CI.
  • A clean result means none of these patterns matched. It does not mean the code is secure.
